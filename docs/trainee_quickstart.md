# 新人试用期快速上手

**面向:刚加入团队的试用员工(trainee)**
**预期用时:首日 30-60 分钟把基础搭好,之后每天 15 分钟走流程**

---

## 一、你会用到什么

| 工具 | 用来做什么 | 何时需要 |
| --- | --- | --- |
| 企业邮箱(Google Workspace) | 收团队消息、登录各平台 | 第一天收到邀请 |
| Telegram + @one23_tech_bot | 每天看当日任务、问教官、提交作业 | 每天 |

## 二、第一天你要做的(按顺序)

### Step 1:收邀请,激活企业邮箱
你的负责人会给你开一个 `yourname@公司域名`。进去后做两件事:
- 登录一次,把密码改成你自己的
- 在 Telegram 上创建或登录你的个人账号(如果还没有)

### Step 2:找到 bot
在 Telegram 里搜 **@one23_tech_bot**,点进去,点 **START** 按钮(或发送 `/start`)。

### Step 3:bot 问你邮箱
bot 会回复:
```
欢迎加入 OneAgents
我是内部助手 bot。第一步:请回复你的企业邮箱,我来把你绑到系统里。
```
你直接回复你的企业邮箱,比如:
```
xiaoming@公司域名
```

若 bot 回:`邮箱 xxx 还没登记。请联系 superadmin 登记` — 说明负责人还没在系统里把你加进去,找他登记后再重来。

若 bot 回:`✅ 已绑定到 xxx (trainee)` — 成功,继续下一步。

### Step 4:回答 3 道入职画像
bot 会依次问 3 个问题:

**问题 1/3:技术背景**
用自然语言说清楚:
- 你做过什么(语言、框架、项目类型)
- 多少年经验
- 哪些是熟练,哪些只接触过

例:
> 3 年前端 React/Vue,做过电商和后台。Node.js 基础,自己做过几个小 API。没做过运维。

**问题 2/3:最薄弱或最想学的**
例:
> 服务器 SSH 操作不熟,英文日志读得慢,想学怎么快速定位生产 bug。

**问题 3/3:学习风格**
例:
> 偏动手先试,遇到问题再查文档。跟着示例改最容易上手。

答完之后,bot 会:
1. 立刻生成你的**员工画像**存进系统(后面 mentor 会根据这个调整引导)
2. **启动 15 天培训程序**(默认配 mentor **Nina**,温和型教练)
3. 直接展示 **Day 1 任务**

## 三、每天的节奏

### 早上:看当日任务

发:
```
/today
```

你会收到:
1. **今日任务标题** 和阶段(比如 "Day 3:基础开发环境连通")
2. **今日目标**
3. **必做清单**(具体做哪些事)
4. **产出物**(要提交什么 — 截图、链接、笔记)
5. **评分重点**(负责人会看这个打分)
6. **mentor 的个性化引导**(200 字左右,Nina 会先肯定再拆步骤)
7. **3 条相关 SOP 片段**(系统自动从知识库检索的)

例:
```
Day 3:基础开发环境连通
阶段一:环境准备 (Day 1-3)
目标:能在本地打开项目并运行基础命令
必做:用 WebStorm 打开仓库、安装依赖、启动项目、读取 README、记录卡点
产出:本地运行截图、问题清单
评分重点:是否能整理问题而不是只说"跑不起来"

教官 Nina:
**今天先别慌**
你前两天工具装得不错,今天开始跑起来。
**一步一步怎么做**
1. WebStorm → File → Open → 选仓库目录
2. 下面弹出 package.json 提示,点 Install
3. 终端运行 npm run dev
4. 如果报错,截图 + 复制错误信息到 note
...
```

### 遇到问题:问 mentor

发:
```
/chat 我运行 npm install 报 ERESOLVE 依赖冲突,怎么办?
```

mentor 会:
- 用她的语气回复(Nina = 温和先肯定;Marcus = 严格直接;Oscar = 先查日志)
- 带**记忆**(她记得你前面问过什么、你是什么背景、你在 Day 几)
- 结合相关 SOP 给具体操作建议

你可以连续问多轮,不用每次自我介绍。

**重要**:bot 的每一次回答都会存进 `mentor_conversations`,superadmin 会看回放来评估培训质量 + 改进 mentor 人设。所以**别怕问蠢问题**,问得越多数据越准。

### 做完事:提交作业

你会拿到一个 `task_id`(在 `/today` 返回里)。用下面的格式提交:

```bash
# 在浏览器或 curl 里发
POST https://oneagents-worker.one-deploy.workers.dev/onboarding/tasks/<task_id>/submit
Authorization: Bearer <你的 bearer token>
Content-Type: application/json

{
  "notes": "完成情况:装好 WebStorm,打开仓库成功。npm install 时遇到依赖冲突,用 --legacy-peer-deps 解决。npm run dev 成功启动,端口 3000。附截图。",
  "uris": ["https://i.example.com/shot1.png", "https://i.example.com/shot2.png"]
}
```

**找 bearer token**:
首次绑定后,负责人会给你一个 `oa_xxxxx` 开头的长串 token。**这个 token 仅见一次,请立刻保存**(存到密码管理器如 1Password/Bitwarden,或至少记在本地 `.txt`)。

如果丢了,找负责人重发。

简化版:后面 `/submit` 指令在 bot 里直接交 — 目前暂时要 curl。

### 评分

你提交之后:
- 负责人会看你的 notes + 截图
- 系统的 **AI 辅助评分** 先打一个初评 + 3 条理由(给负责人参考)
- 最终分由**人工决定**,会写进 `onboarding_tasks.score`

你可以随时发 `/chat 帮我回顾 Day 3 的评分` 问 mentor。

## 六、5 维评分怎么算

最终分按这 5 维加权:

| 维度 | 权重 | 怎么评 |
| --- | --- | --- |
| 环境配置能力 | 20% | 前 3 天能否独立装完工具 / 配 SSH / 启动本地 |
| 协作能力 | 20% | 是否会用 GitHub 分支 / commit / PR,是否按汇报格式写东西 |
| 执行能力 | 25% | 能否独立推进小任务不等人 |
| 排查能力 | 15% | 遇到错报不慌,有结构化定位 |
| 文档与沟通 | 10% | 纪要 / 任务汇报是否清楚简洁 |
| 责任感与稳定性 | 10% | 按时反馈,遇阻不卡死 |

注意:**AI 给的初评不是最终分**。最终由负责人判断,尤其是"排查能力"和"责任感"这类非机械维度。

## 七、碰到问题该做什么(按顺序试)

1. **先自己查 15 分钟**:Google 错误信息、看项目 README、看 SOP 检索返回
2. **问 mentor**:`/chat` 详细描述问题 + 你试过什么 + 报错截图描述
3. **@ 负责人**:如果 mentor 也没解决,在 Telegram 直接找你的 mentor 负责人
4. **记录问题**:每天把卡住超过 30 分钟的问题记在提交的 `notes` 里 — 这能帮系统改进培训资料

**什么情况不要硬扛**:
- 怀疑碰到了生产环境 / 客户数据(立即停)
- 要修改你觉得"不太对"的 API key / 服务器 / DB(立即停)
- 总之:**动数据前,不确定就先问**

## 九、FAQ

**Q: 我没收到 /today,会自动提醒吗?**
A: 目前不会主动推送,要自己发 `/today`。下一版会加"每天早上 9 点自动推"。

**Q: 我能重做昨天的任务吗?**
A: 系统不阻止,但评分已经给过的话需要负责人在 Supabase 里改。

**Q: 我能切 mentor 吗?**
A: 你不能,负责人可以。可以跟负责人说"Day 5 后我想试 Oscar 风格",他改一条 SQL 就行。

**Q: `/chat` 的 mentor 是真人还是 AI?**
A: AI(走 Vercel AI Gateway,默认 Claude Haiku)。它基于 mentor 的人设模板 + 你的历史对话 + 相关 SOP 回答。**最终打分是真人**。

**Q: 我想看自己的培训总览在哪里?**
A: `GET /onboarding/programs/<program-id>/summary` 返回 15 天分阶段打分。下一版会加 bot 指令 `/me_summary`。
